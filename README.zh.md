# dsh-model-dispatch

[English](README.md) | 中文

**让 DeepSeek Harness（DSH）的主对话、子代理和计划模式各用各的模型。**

不装插件时，子代理默认继承主模型，计划模式也用主模型。装上以后可以分开选，例如：平时对话用又快又便宜的模型，制定计划时换成最强的模型，派出去干活的子代理再用另一个。选一次就生效，之后由插件保证它们真的在用你选的模型。

> 本插件基于 [lincong1987/dsh-model-switch](https://github.com/lincong1987/dsh-model-switch)（只支持 DSH 0.1.x）的设计与代码，为 DSH 0.2.x 重写并扩展，详见[致谢](#致谢)。

## 三个角色，分别选模型

| 角色 | 什么时候在工作 | 在哪里选 |
|---|---|---|
| **主模型** | 你和 DSH 的日常对话 | 聊天输入框的“主模型”芯片（只改当前会话）；设置页“新会话默认模型” |
| **子代理** | 主代理派出去干活的子代理 | 聊天输入框的“子代理”芯片（只改当前会话）；设置页“子代理默认模型” |
| **计划模型** | 计划模式（`/plan`）里制定计划的阶段 | 设置页“制定计划模型” |

每一项都可以连同思考强度一起选。DSH 里配置好的模型全部可选，新加的模型会自动出现在菜单里。

## 插件替你保证的事

- **选了就锁定**：子代理一创建就锁定模型和思考强度，续聊、重试、重启都不变。即使主代理在调用工具时要求换别的模型，也以你的选择为准。
- **计划做完自动换回来**：进入计划模式时临时换成计划模型；批准计划或 `/plan off` 后，从第一条执行请求起恢复原来的主模型和思考强度。
- **聊天里的选择不动默认**：在聊天栏改的只影响当前会话。新会话用什么模型，只由设置页决定。
- **出问题就停下，不偷偷换模型**：模型不可用、配置损坏或保存失败时，请求会停住并说明原因，不会悄悄改用别的模型。

## 安装

任何 DSH 版本都可以安装，不需要本地构建。

1. 等 DSH 里正在跑的任务结束。
2. 运行安装命令，把 `desktop` 换成你实际使用的 profile：

   ```bash
   dsh plugin --profile desktop add github:hina1016/dsh-model-dispatch
   ```

3. **完全退出 DSH，再重新打开。** 只刷新页面不够：那样只会加载界面部分，负责锁定模型的宿主部分要重启才生效。

## 使用

### 1. 在设置页定好默认

打开 DSH 设置里的“模型切换”，有三项：

| 设置项 | 作用 | 不设置时 |
|---|---|---|
| 新会话默认模型 | 以后新开的会话用它 | 用 DSH 自己的默认 |
| 子代理默认模型 | 子代理默认用它 | 跟随主模型 |
| 制定计划模型 | 计划模式下用它 | 跟随主模型，也就是不换 |

### 2. 在聊天里随时换

输入框上有 **主模型** 和 **子代理** 两个芯片，各自写着当前的模型和思考强度（窗口较窄时只显示模型名）。点开是同一个菜单：

1. 搜索，或从收藏、最近使用、提供方分组里选一个模型。
2. 菜单不会关，接着在底部调思考强度。
3. 点 **应用** 保存。点取消、按 Esc 或点菜单外面，都不会保存任何东西。

两个芯片的作用范围：

- **主模型**芯片只改当前会话。
- **子代理**芯片显示的就是之后新建的子代理会用的模型。改它只影响此后新建的子代理，已经在跑的子代理保持原来的模型。想回到默认，直接在列表里把默认的那个模型选回来。

### 3. 计划模式会发生什么

```text
平时对话（主模型）
   │  /plan
   ▼
制定计划（计划模型）── 拒绝计划 ──▶ 留在计划模式，继续用计划模型
   │  批准计划，或 /plan off
   ▼
执行（恢复进入计划前的主模型和思考强度）
```

审批面板上会写明执行时将恢复成哪个模型。子代理不参与这个切换，始终用自己锁定的模型。

### 4. 收藏常用组合

菜单里的 ★ 收藏的是“模型 + 思考强度”的组合。同一个模型的多个强度合并成一行标签，点一下就用。点模型名时，会自动带上你上次给它用的强度。完整规则见[收藏模型与思考强度](docs/favorite-efforts.md)。

## 子代理到底用哪个模型

按下面的顺序，取第一个有值的：

1. 你在本会话的“子代理”芯片里选的模型；
2. 设置页的“子代理默认模型”；
3. 主会话当前的模型。

模型和思考强度作为一个整体锁定。子代理再派出的子代理，继承同一个锁。完整规则见 [1.2.0 路由锁定](docs/releases/1.2.0-route-locking.md)。

## 常见问题

**装完之后界面没有变化？**
需要完全退出 DSH 再打开，只刷新页面不行。

**芯片上出现 ⚠，或者设置页顶部提示“功能已降级”？**
当前的 DSH 少了插件需要的某个接口，通常发生在 DSH 升级之后。提示里写明了受影响的功能和缺少的接口名，其余功能照常。可以更新插件，或把提示原文贴到 issue 里。各种降级的含义见 [1.3.0 说明](docs/releases/1.3.0-host-seams.md)。

**子代理标题栏显示“待确认模型，已暂停请求”？**
这是没有锁定记录的老子代理，常见于升级到 1.2.0 之前创建的子代理。打开它，在标题栏展开“待确认模型”，选好模型和思考强度后点“应用”，它会保留原来的上下文继续工作。

**子代理一启动就报 `Cannot read properties of undefined (reading 'parent')`？**
这是 1.3.0 在 DSH 0.2.2-rc.3 上的问题：宿主改了启动子代理时传的参数形状。升级到 1.3.1 即可。

**主代理在工具参数里指定了别的模型，为什么没生效？**
这是有意的：子代理用什么模型由你决定，不由模型自己决定。界面会提示“已忽略工具或预设的冲突选模”。

**改了子代理模型，正在跑的子代理为什么没变？**
已创建的子代理保持锁定。新的选择只对之后新建的子代理生效；想让某个任务换模型，新建一个子代理。

**保存时提示模型无效？**
插件在保存前会向 DSH 核对“提供方 + 模型 + 思考强度”这个组合是否真实可用。名字相近的提供方不能互换，请从菜单里正确的提供方分组重新选。

**换了电脑，收藏和最近使用不见了？**
它们存在浏览器本地，不随账号同步。模型设置和锁定记录不受影响。

**支持哪些 DSH 版本？**
任何版本都能装，能用哪些功能取决于 DSH 提供了哪些接口。跑通过完整测试的版本列在[已验证版本](docs/verified-versions.md)，它是参考，不是安装条件。

## 数据存在哪里

| 数据 | 位置 |
|---|---|
| 子代理默认模型、制定计划模型 | DSH profile 配置，在设置页或配置文件里都能改 |
| 新会话默认模型 | DSH 原生的 `agent-default-model` 配置项 |
| 各会话的子代理选择 | `$DSH_HOME/storages/model-switch/session-overrides.json` |
| 子代理的模型锁 | `$DSH_HOME/storages/model-switch/child-route-locks.json` |
| 进入计划前的主模型 | `$DSH_HOME/storages/model-switch/plan-main-models.json`，恢复成功后清除 |
| 收藏、最近使用、上次强度 | 浏览器 localStorage 的 `dsh-model-switch/picker-v2`，不同步设备 |

升级插件不需要迁移这些数据。

## 开发与验证

```bash
npm ci
npm test            # vitest
npm run typecheck   # 宿主与客户端两个工程
npm run build       # 输出到 lib/
npm run preview     # 模型菜单可交互预览，http://127.0.0.1:5179/
```

`lib/` 是提交进仓库的构建产物，用户直接从 GitHub 安装；修改 `src/` 后要重新构建，并和源码放在同一次提交里。

在完整的 DSH 宿主上跑契约测试，使用模拟模型，不产生付费请求：

```bash
DSH_TEST_MODULE_ROOT=/绝对路径/dsh/node_modules node scripts/verify-host.mjs
```

脚本使用独立的临时 profile，不碰你正在用的桌面 profile。它核对原生工具、嵌套委派、请求头和适配器调用，并断言工具参数想换用的模型（测试里是模拟的 Opus）一次都没有被派发、接缝报告为空。CI（`.github/workflows/regression.yml`）在每个列出的 DSH 版本上运行它，也可以手动触发并输入任意版本；结果的记录方式见[已验证版本](docs/verified-versions.md)。

实现要点：

- 保存选择和创建子代理之前，通过宿主的 `resolveCallConfig` 校验 provider、model、effort 的真实组合，无效组合当场报错。
- 子代理创建时原子写入模型锁，每次请求组装和派发前校验；最终的 `llm/stream` 守卫只放行或拒绝，不改写请求。
- 模型发现工具只报告用户锁定的路由，不能自行改选。
- 用 `AsyncLocalStorage` 隔离原生 `selectModel` 把模型写成部署默认的副作用，只拦这一条调用链，所以会话内换模和计划换模都不会改动新会话默认。

更多文档：[文档索引](docs/README.md)、[术语表](GLOSSARY.md)、[ADR 0001](docs/adr/0001-host-seams-not-versions.md)；在本仓库工作的 Agent 先读 [AGENTS.md](AGENTS.md)。

## 已知限制

- 插件只能确认 DSH 提供了它需要的接口，确认不了这些接口的行为没变。事件改名、时序变化要靠契约测试发现，所以每个新的 DSH 版本都需要跑一遍。
- 识别“计划已批准”依赖 DSH 的事件格式；DSH 改了格式，需要重新验证。
- 子代理内部不参与计划换模，始终用自己的锁；它派出的子代理继承这个锁。
- 有些外部后端无法保证实际使用的模型，这类后端上的子代理会被拒绝启动。配置或锁出问题时需要你修复或确认，没有自动换模兜底。
- 界面上的“最近放行请求”表示插件放行了这条路由的请求，不代表模型提供方已成功返回，也不代表已计费。
