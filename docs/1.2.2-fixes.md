# 1.2.2 — compaction, route status and plan restoration

This patch keeps 1.2.1's Windows directory-sync compatibility and the existing user-owned child-model lock policy.

- A child compaction request may omit reasoning effort only during an observed native compaction transaction for that exact live child. Ordinary loop requests still require the full locked selection. Child identity, parent ownership, provider and model remain mandatory. Explicit effort conflicts are rejected. A `purpose: compaction` string alone grants no exception. Auxiliary request facts reflect the envelope actually admitted; the adapter may supply the target model's default effort.
- Mismatch errors identify the differing fields and show missing effort as `<default>`.
- Saved choices for existing sessions without a live agent report `unverified`, after checking configured-model availability. They remain editable and receive no ready checkmark. Missing sessions report `missing`; invalid selections remain blocked. Creation and every paid request retain the enforcement checks.
- Applied plan-routing transitions are tracked separately from native plan projections. A saved original main selection is restored before the first execution request, even if `plan/mode:false` was committed before pre-step. Restore failures retain the saved selection for retry.
- The review endpoint waits for the original-model store. Initialization failures return 503 rather than a successful empty snapshot. The panel distinguishes failure from loading and offers retry; stale responses from an earlier session are ignored.
- Native-host assertions and reports read the plugin version from `package.json`. Test-home links use junctions on Windows. Harness failures explicitly set a failing exit code.

## Verification

`npm ci`, `npm test`, `npm run typecheck` and `npm run build` check installation, routing, persistence and the client components. Windows filesystem tests simulate both unsupported directory open/sync operations and real file write/rename permission failures; only the former are tolerated.

`node scripts/verify-host.mjs` uses an isolated, marker-protected DSH home and mock adapters. Set `DSH_TEST_MODULE_ROOT` to an absolute official DSH `node_modules` directory. It exercises actual native child delegation, native compaction, wrong-model/effort rejection during compaction, missing and dormant session status, mid-chat planning, approval, idle `/plan off`, cold continuation and independent defaults. No real model account or paid request is needed. Expensive-model dispatches must remain zero.

The workflow template in `docs/ci/regression.yml.example` defines unit/build checks on Windows, macOS and Linux, and the rc.3 native harness on Windows and macOS. It is not active: installing it as `.github/workflows/regression.yml` requires GitHub workflow permission. Local macOS results and Windows CI results must be reported separately: simulated Windows filesystem failures are not a Windows Desktop end-to-end test.

The upgrade takes effect when DSH reloads the plugin or restarts. Finish running tasks before restarting. Existing persisted model locks and settings are retained; no data migration is required.
