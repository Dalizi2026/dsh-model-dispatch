# 1.3.0：按宿主接缝运行，版本只作证据

从 1.3.0 起，插件不再按 DSH 版本号拦截安装：`engines.dsh` 为 `*`，DSH 系列 peer 只保留包名（范围 `*`，仍为 optional）。能不能运行由[宿主接缝](../GLOSSARY.md)决定：每项[能力](../GLOSSARY.md)在用到时检查自己依赖的接缝，缺了就降级，并告诉用户缺了哪些接缝。决策理由见 [ADR 0001](adr/0001-host-seams-not-versions.md)，哪些 DSH 版本跑通过契约测试见[已验证版本](verified-versions.md)。

## 能力与降级

各项能力缺了就不能安全运行的宿主接缝，统一登记在 `src/host-seams.ts` 的 `REQUIREMENTS` 里。新增这类依赖时必须同时登记；可选接缝（例如 `tools.get`、`llm.resolveModelInfo`、`planMode`）在调用处先判断存在，缺了只少对应的辅助行为，不能让请求失败。

- **模型锁**：需要 `subagents` 的启动入口（`startActivation`、`startContinuable`、`start` 至少一个）和 `getProvider`，以及 `agents.get`、`sessionPersistence.stat`、`llm.resolveCallConfig`、`llm.listProviders`、`llm.listModels`。
  - 缺任一项：暂停子代理派发和子代理请求，主会话照常。宿主补齐后自动恢复，不需要重启。
  - 压缩事件里读不到 `compactionId`：子代理的压缩请求不放宽思考强度检查，宁可拦下，并报告数据格式不符。
- **计划自动换模**（包括新会话默认保护）：需要 `sessionController.selectModel`、`agentDefaultModel.saveSelection`、`sessionProjections.stateOf`、`sessionProjections.register`。
  - 缺任一项：整项关闭，计划模式照常可用，但不自动换模。两项必须一起开关，因为没有默认保护时，原生 `selectModel` 会把临时的计划模型写成新会话默认。
  - `exit_plan_mode` 的结果里读不到布尔值 `approved`：只靠计划模式的退出事件恢复主模型，可能晚一步，并报告数据格式不符。
- **界面入口**：客户端顶层只依赖 `slots` 和 `locale`，其余服务由各入口自己注入，缺哪个只少哪个入口，DSH 原生入口保留。
  - 聊天栏模型芯片需要 `configForms`、`remote`、`remote.session`、`sessions`。
  - 子代理目录需要 `sessions`、`uiWorkspace`。
  - 设置页需要 `configForms`。设置页、计划审批面板和子代理标题徽标在读取模型目录时才使用 `remote.session`，缺了就在加载错误里写明这个接缝名。

插件与客户端之间的 HTTP 通道依赖 `webServer.register` 和 `connection.admit`。缺 `connection.admit` 时接口返回 503，并写明这个接缝名；缺 `webServer.register` 时客户端收不到任何状态，只能从宿主日志里看到插件的失败记录。

插件不再声明顶层 `inject`。原先的 `inject = ['subagents']` 会让插件在 `subagents` 缺失时整个不启动，一个守卫都不挂，子代理照宿主原生方式继承主模型。

## 提示

提示文案先写影响，再写可能的原因，最后列出原样的接缝名，方便直接贴进 issue。提示不写 DSH 版本号。

- **聊天栏子代理芯片**：任一能力降级时显示 ⚠，点开可以看到详情；模型锁暂停时会自动展开。数据跟着现有的 4 秒路由状态请求（`route-status` 的 `seams` 字段）一起返回，不增加请求。
- **设置页顶部**：横幅列出所有降级的能力，包括客户端入口。打开设置页时读一次 `/_dsh/model-switch/host-seams`，之后不轮询。
- **宿主日志**：某项能力的检查结果变化时记一条，降级时 warn，恢复时 info；结果没变就不重复记。

只有被问到时（委派、请求、组装、状态读取）才检查，结果不缓存，也没有定时器。常驻内存的只有每项能力上一次记日志时的结果，以及观察到的事件格式不符记录。

## 运行时查不到的变化

运行时检查只能确认接缝存在，确认不了行为没变。下面这些变化只能靠在每个版本上运行 `scripts/verify-host.mjs` 来发现：

- 事件改名：宿主没有事件注册表，监听不会报错，只是永远不触发。`llm/stream` 仍是派发前的最后一道守卫。
- 时序变化：比如 0.2.2 把模型选择从 `system-prompt/assemble` 挪到了更早的 `agent/pre-step`，见[已验证版本](verified-versions.md#022-rc1未通过)。
- 模块导出缺失：会在加载时报导入错误，报错显眼，但看不出缺的是哪个接缝。

契约测试最后会检查 `host-seams` 报告为空。到那时压缩和计划审批都已经跑过，所以报告为空也说明这两类事件的数据格式符合预期。

## 升级

安装 1.3.0 后完全退出并重新打开 DSH。已保存的设置、会话覆盖和模型锁都不需要迁移。CI 模板已经改为生效的 `.github/workflows/regression.yml`：它会在每个列出的 DSH 版本上运行原生宿主测试，也可以通过 `workflow_dispatch` 输入任意版本。
