# 1.2.3 — DSH Desktop 0.2.1-rc.5

The compatibility baseline is Desktop 0.2.1-rc.5, which is the official main release channel. The separate 0.2.2-alpha.2 channel is not included in this claim.

- Development packages and generated client/host types are aligned with 0.2.1-rc.5. The lockfile is regenerated against a clean dependency tree to avoid mixing exact rc.3 and rc.5 peer dependencies.
- Plugin package and runtime version are 1.2.3. The optional peer ranges continue to admit the previously supported 0.2.x hosts.
- The upstream rc.3-to-rc.5 changes were checked against the delegation, model-selection, plan-mode, compaction and client-slot contracts. They do not require changing this plugin's routing policy.
- User-owned child-model locks, compaction checks, historical confirmation, independent defaults and temporary planning-model restoration are retained.
- The CI configuration template targets rc.5; the template is not an active GitHub workflow.

## Verification

133 tests (19 files), both host/client TypeScript checks and the build pass with the rc.5 development packages.

In isolated native hosts with mock adapters:

- 0.2.1-rc.5: all 10 initial scenarios pass, covering delegation conflicts, nested delegation, native compaction, auxiliary route rejection, historical-session status, mid-chat planning, approval, idle `/plan off`, cold continuation and independent defaults.
- A new process resumes the locked child after defaults change; its original context survives compaction and restart.
- A historical child without a lock pauses before adapter dispatch. Only authenticated human confirmation with a matching parent allows it to continue with its retained context.
- 0.2.1-rc.3: all 10 initial scenarios continue to pass.

The native checks run on macOS, with zero real paid requests and zero simulated Opus dispatches. Windows filesystem fault tests remain covered by the unit suite; Windows Desktop has not been tested in person for this release.

## Upgrade

Install the 1.2.3 package and restart DSH after running tasks finish. Existing settings and persisted locks require no migration. A Desktop upgrade and a plugin upgrade are separate operations.
