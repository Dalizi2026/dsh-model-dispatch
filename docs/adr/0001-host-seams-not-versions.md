# 0001 插件能否运行由宿主接缝决定，版本号只作验证证据

DSH 在安装和启动插件时，会按 `engines.dsh` 或 DSH peer 的版本范围拦截插件。插件以前用 `^0.2.0-rc.2 || ^0.2.1-rc.1` 挡住宿主变化，但这样一来，接缝没变的宿主升级也会被拦下；而且这个声明已经和实际情况对不上了（预发布版本参与范围匹配，0.2.2-rc.1 照样能加载）。现决定：`engines.dsh` 设为 `*`，DSH peer 只保留包名（范围 `*`，仍为 optional）。插件总是启动并先挂守卫。每项[能力](../../GLOSSARY.md)在用到时只检查自己需要的[宿主接缝](../../GLOSSARY.md)，事件数据格式对不上也算缺接缝。缺接缝的能力降级，界面写明影响和缺少的接缝名：

- 模型锁缺接缝时，拦下子代理派发，不放行。
- 计划自动换模和新会话默认保护一起关闭。
- 界面入口缺哪个就只少哪个。

版本号只记在已验证版本记录里，由契约测试生成。

## Considered Options

- **保留版本下限 `>=0.2.0-rc.2`**：否决。0.1.x 宿主缺少所需接缝，接缝检查本身就会拦下，下限是多余的；而且它仍然是在用版本号代替接缝判断。
- **缺接缝时整个插件不启动**（原先的顶层 `inject = ['subagents']`）：否决。插件不启动，就一个守卫都不会挂上，宿主照原生方式让子代理继承主模型，锁失效了却没人知道。
- **只放开版本，不做运行时检查**：否决。接缝缺失时功能会悄悄失效。
- **启动和热更新时集中检查一次**：否决。宿主服务是陆续注册的，启动时检查会把还没注册的服务误判为缺失，而且结果要常驻内存。按需检查空闲时没有开销，热更新后查到的也自然是新结果。
- **在未验证的 DSH 版本上提示用户**：否决。插件里要内置一份版本清单，和已验证版本记录形成两处来源，等于把版本号带回运行时。

## Consequences

- 运行时检查只能确认接缝存在，确认不了行为没变，也发现不了事件改名。这部分靠在每个已验证版本上运行契约测试（`scripts/verify-host.mjs`）来兜底；`llm/stream` 仍是派发前的最后一道守卫。
- 新的 DSH 版本发布后，用户可能在验证完成之前就装上它。已验证版本记录只用来告知，不是安装条件。
