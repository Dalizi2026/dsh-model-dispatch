## 子代理无法启动

### 现象

2026-11-16 用户在 DSH Desktop 0.2.2-rc.3 上报告：一个会话里对 `subagent`、`subagent_fork` 和 `workflow` 的 `agent()` 共 6 次调用，全部立即返回同一个错误，子代理没有创建，请求没有到达任何模型：

```text
Error: Cannot read properties of undefined (reading 'parent')
```

主会话不受影响。只要装着 1.3.0，这台宿主上的任何子代理都启动不了。

### 根因

宿主改了原生启动入口 `subagents.startActivation(spec)` 的参数形状，插件只认旧的那一种：

| 宿主 | 父代理的位置 | 模型选项的位置 |
|---|---|---|
| 0.2.1-rc.5、0.2.2-rc.1 | `spec.request.parent` | `spec.request.agentOptions` |
| 0.2.2-rc.3 | `spec.parent` | `spec.agentOptions` |

`src/subagent-routing.ts` 在包装 `startActivation` 时直接读 `spec.request.parent`。0.2.2-rc.3 的 `spec` 上没有 `request`，于是在进入路由判断之前就抛出了 TypeError。

这属于[宿主接缝](../../GLOSSARY.md)的数据格式变化，但这个依赖当时没有登记，所以既没有降级提示，也没有可读的报错。CI 的宿主版本清单里也没有 0.2.2-rc.3，契约测试没有机会发现它。

### 修复

- **两种形状都读**：先看 `spec.request` 里有没有父代理，没有再看 `spec` 本身。改写模型选项后，按原来的形状交还宿主：嵌套的仍然嵌套，平铺的仍然平铺，其余字段原样保留。
- **读不到就拦下，不再抛异常**：两种形状都找不到父代理时，按缺接缝报告：拦下这次启动，报错写明接缝名 `subagents start request.parent`，聊天栏芯片、设置页横幅和宿主日志同步显示“子代理派发已暂停”。已经持有模型锁的子代理不受影响，照常发请求。之后只要有一次读得到，标记自动清除。所有启动入口共用这一个标记，一个入口的坏请求不会拦住其他入口的正常请求。
- **接缝登记**：`HostSeams.observe` 增加一个参数，用来标明“缺了这份数据就没法工作”。这类不符计入 `missing`，而不是 `mismatched`（保守运行）。规则补进了 [1.3.0 说明](1.3.0-host-seams.md#能力与降级)。
- **CI**：`.github/workflows/regression.yml` 的默认宿主版本清单加入 0.2.2-rc.3。

改动的文件：`src/subagent-routing.ts`、`src/host-seams.ts`、`src/route-enforcer.ts`、`src/route-contract.ts`（只改注释），以及 tsc 重新生成的 `lib/` 对应文件。客户端代码和客户端 bundle 没有变化。

### 验证

- **全量检查**：`npm test` 23 个文件、179 项全部通过；`npm run typecheck` 通过。
- **契约测试**：用 `scripts/verify-host.mjs` 在官方 0.2.2-rc.3 运行时上跑，模拟模型，付费请求 0。
  - 修复前（提交 `7f95807` 的 `lib/`）：初始阶段 0 个用例通过。原生 `subagent` 工具返回的正是上面那条错误，子代理没有创建。
  - 修复后：初始 10 个、`resume` 2 个、`historical` 3 个用例全部通过，接缝报告为空，模拟 Opus 派发 0。记录见[已验证版本](../verified-versions.md)。

## 子代理目录被裁切

> 来源：DSH Skin 工作区 1.0.72 修复方案中的缺陷 B1。已在 Desktop 实机确认，根因不在皮肤。

### 结论

- **现象**：点击会话头部「N 个子智能体」后，按钮变为 `aria-expanded="true"`，目录 `role="tree"` 已渲染，但界面上看不到；按 Escape 能关闭。
- **根因**：`SubagentCatalogAction` 把菜单作为头部内部的 `position: absolute` 子节点渲染。宿主 0.2.2-rc.1 的 `ConversationRoot` 给标题区 `._titleCluster` 设了 `overflow: clip` 和左向渐隐 `mask-image`，标题区以下的内容全部被裁掉。
- **修复方向**：与宿主原生目录一致，菜单用 `createPortal` 挂到 `document.body`，以 `position: fixed` 按触发按钮定位。宿主和皮肤都不改。

### 现场证据

- **环境**：DeepSeek Harness Desktop 0.2.2-rc.1（Electron 44.7.0 / Chrome 152），darwin，浅色，窗口 1483×942。已装皮肤 dsh-skin-endfield-zhuangfangyi 1.0.71、本插件 1.3.0、dsh-context 0.82.2。通过 CDP 9222 使用真实点击（`Input.dispatchMouseEvent`）复现。
- **目录节点**：矩形 672,44，336×258。`elementFromPoint` 在目录中心命中的是对话页签与正文，不是目录。
- **标题区**：实测矩形 297,7，1111×36。宿主样式摘录：
  `._titleCluster { …; mask-image: linear-gradient(to left, transparent calc(.3 * var(--title-cluster-fade)), #000 var(--title-cluster-fade)); overflow: clip }`
- **排除皮肤**：禁用全部皮肤样式表后，目录依旧不可见；皮肤没有任何规则作用于 `titleCluster` 的 overflow 或 mask。
- **宿主原生实现**：`@deepseek-ai/dsh-client-ui-subagent` 0.2.2-rc.1 的 `CatalogDropdown` 用 portal 挂到 `document.body` 并 fixed 定位，所以不受这层裁切影响。
- **截图**：保存在本机 DSH Skin 工作区的 `dsh-skin-endfield-zhuangfangyi/qa/2026-11-09-host-inheritance/live/`（`b1-click-menu-open.png`、`b1-skin-off-menu-open.png`）。截图含个人会话内容，不放进本仓库。

### 实际改动

- 新增并导出 `catalogMenuPosition`：菜单宽度与 CSS 的 336px 对齐，水平方向保留 16px 视口边距，顶部保持原触发按钮下方 5px 的间距。
- 打开时从触发按钮的 `getBoundingClientRect()` 同批计算位置；触发节点为空则不打开。关闭及目录自动隐藏时清空位置，只有 `open` 且位置有效时才渲染菜单。
- 菜单通过 `createPortal(..., document.body)` 挂载，继续使用宿主写在 body 上的 `--dsw-*` token；`.menu` 改为 `position: fixed`，位置由内联 `top` / `left` 提供，原有层级、尺寸、背景和阴影不变。
- 外部点击同时检查 `rootRef` 与 `menuRef`：目标位于菜单内时不关闭，避免行、展开箭头和重试按钮在 `pointerdown` 阶段被提前卸载。
- 键盘导航从 `menuRef` 查询可聚焦 treeitem。`onKeyDown` 仍只挂在 root，利用 React portal 的合成事件冒泡，不增加第二处处理器。
- 打开期间监听 `window.resize` 与 document 捕获阶段的 `scroll`，重新计算位置；关闭和卸载时移除监听。

### 实机验收

2026-11-15 至 11-16 在 DSH Desktop 0.2.2-rc.3（macOS，窗口 1280×820，皮肤 dsh-skin-endfield-zhuangfangyi 1.0.72 保持安装）上完成，由 Agent 通过 9222 调试端口用真实点击和按键执行，用户批准了安装、重启和接管窗口。

- **结论**：深色、浅色两个主题下第 1 至 4 项和第 6 项都通过；展开箭头和第 5 项没有验到，原因见下。
- **被验收的版本**：用 `npm pack --ignore-scripts` 把工作区打成安装包，以 `file:` 方式装进 desktop profile；已安装的 `lib/client.js` 与工作区逐字节一致。没有重新构建：`npm run build` 的 tsc 两步输出与现有 `lib/` 完全一致，tsdown 一步卡在读取 `node_modules` 里被 iCloud 移出本地的文件，已中止；现有 `lib/client.js` 是 11 月 9 日在最后一次源码修改之后构建的。
- **此前的安装记录**：11 月 9 日记录的本地 `link:` 安装在 11 月 15 日复核时已不在，profile 装的是 `github:hina1016/dsh-model-dispatch#v1.3.0`，不含本修复。rc.3 的标题区仍是 `overflow: clip` 加渐隐 `mask-image`，根因仍在。
- **验收对象**：一个带 2 个子代理的会话，头部按钮为“2 个子智能体”。
- **验收项**：

  2. 部分通过：点击目录内部不属于任何一行的位置，目录保持打开；点行后打开对应子会话，目录关闭。展开箭头没有验到，因为这两个子代理都没有下级，界面上没有箭头。
  3. 通过：点击目录外的空白处关闭；Escape 关闭并把焦点还给触发按钮；焦点在按钮上按 ArrowDown 打开并聚焦第一行；ArrowDown、ArrowUp、End、Home 依次把焦点移到第 2 行、第 1 行、末行、首行。
