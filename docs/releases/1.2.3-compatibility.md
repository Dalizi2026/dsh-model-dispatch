# 1.2.3：对齐 DSH Desktop 0.2.1-rc.5

| 类型 | 插件版本 | 宿主 | 日期 | 状态 |
|---|---|---|---|---|
| 版本说明 | 1.2.3 | DSH 0.2.1-rc.5 | 2026-11-04 | 历史 |

[← 文档索引](../README.md)

> 历史记录：1.3.0 起 DSH 版本不再是安装条件，见[已验证版本](../verified-versions.md)和 [ADR 0001](../adr/0001-host-seams-not-versions.md)。

本版对齐的宿主是 Desktop 0.2.1-rc.5，即官方主发布通道。独立的 0.2.2-alpha.2 通道不在本次声明范围内。

## 变更

- 开发依赖包和生成的客户端、宿主类型对齐到 0.2.1-rc.5。锁文件在干净的依赖树上重新生成，避免精确版本的 rc.3 与 rc.5 peer 依赖混用。
- 插件包与运行时版本为 1.2.3。可选 peer 范围继续接纳此前支持的 0.2.x 宿主。
- 对照委派、选模、计划模式、压缩和客户端槽位的契约，检查了上游 rc.3 到 rc.5 的改动，不需要修改本插件的路由策略。
- 用户决定的子代理模型锁、压缩检查、历史子代理确认、默认设置隔离和临时计划模型的恢复都保留。
- CI 配置模板指向 rc.5；该模板当时还不是生效的 GitHub workflow。

## 验证

133 项测试（19 个文件）、宿主与客户端两个 TypeScript 检查以及构建，在 rc.5 开发依赖下全部通过。

在使用模拟适配器的隔离原生宿主中：

- 0.2.1-rc.5：初始 10 个场景全部通过，覆盖委派冲突、嵌套委派、原生压缩、辅助路由拒绝、历史会话状态、对话中途进入计划、审批、空闲时 `/plan off`、冷启动续聊和默认设置隔离。
- 默认设置改变后，新进程恢复已锁定的子代理；它的原上下文在压缩和重启后保留。
- 没有锁的历史子代理在适配器派发前暂停。只有经过认证、且父会话匹配的人工确认，才允许它带着保留的上下文继续。
- 0.2.1-rc.3：初始 10 个场景继续全部通过。

原生检查在 macOS 上运行，真实付费请求 0，模拟 Opus 派发 0。Windows 文件系统故障测试仍由单元测试覆盖；本版本没有在 Windows Desktop 上实机测试。

## 升级

安装 1.2.3 包，等运行中的任务结束后重启 DSH。已有设置和持久化的锁不需要迁移。升级 Desktop 与升级插件是两件独立的事。
