> 下面的行为规则至今有效。“验证”一节提到的 CI 模板已在 1.3.0 改为生效的 workflow，见 [1.3.0 说明](1.3.0-host-seams.md#升级)。

本补丁保留 1.2.1 对 Windows 目录同步的兼容处理，以及[子代理模型锁由用户决定](1.2.0-route-locking.md)的既有策略。

## 变更

- **子代理压缩请求**：只有在观察到针对这个存活子代理的原生压缩事务期间，它的压缩请求才可以不带思考强度。普通循环请求仍须带完整的锁定选择；子代理身份、父会话归属、provider 和 model 始终必填。显式给出的强度与锁冲突时拒绝。只有一个 `purpose: compaction` 字符串不构成例外。辅助请求的事实记录反映实际放行的请求；适配器可以补上目标模型的默认强度。
- **不匹配报错**：写明哪些字段不同，缺少强度时显示为 `<default>`。
- **路由状态**：已有会话没有存活 agent 时，保存的选择在核对所配模型可用后报告为 `unverified`，仍可编辑，不显示就绪对勾。会话不存在时报告 `missing`；无效选择仍然阻止。创建子代理和每一次付费请求的强制检查不变。
- **计划恢复**：已应用的计划换模过渡与原生计划投影分开跟踪。即使 `plan/mode:false` 在 pre-step 之前就已提交，保存的原主模型选择也会在第一条执行请求前恢复。恢复失败时保留保存的选择，可以重试。
- **审批面板接口**：等原主模型存储就绪后再响应；初始化失败返回 503，不再返回成功的空快照。面板区分失败与加载中，并提供重试；来自之前会话的过期响应被忽略。
- **测试工具**：原生宿主的断言和报告从 `package.json` 读取插件版本；Windows 上测试目录的链接使用 junction；测试工具失败时显式设置失败退出码。

## 验证

`npm ci`、`npm test`、`npm run typecheck` 和 `npm run build` 检查安装、路由、持久化与客户端组件。Windows 文件系统测试同时模拟“不支持目录 open/sync”和真实的文件写入、重命名权限失败；只有前者被容忍。

`node scripts/verify-host.mjs` 使用带标记保护的隔离 DSH home 和模拟适配器，需要把 `DSH_TEST_MODULE_ROOT` 设为官方 DSH `node_modules` 的绝对路径。它实际跑原生子代理委派、原生压缩、压缩期间的错误模型与强度拒绝、缺失与休眠会话的状态、对话中途进入计划、审批、空闲时 `/plan off`、冷启动续聊和默认设置隔离。不需要真实模型账号，也不产生付费请求；昂贵模型的派发次数必须保持为 0。

`docs/ci/regression.yml.example` 里的 workflow 模板定义了 Windows、macOS、Linux 上的单元与构建检查，以及 Windows、macOS 上的 rc.3 原生宿主测试。它在 1.2.2 时还没有生效：安装成 `.github/workflows/regression.yml` 需要 GitHub workflow 权限。本地 macOS 结果与 Windows CI 结果必须分开报告：模拟的 Windows 文件系统故障不等于 Windows Desktop 端到端测试。

## 升级

DSH 重新加载插件或重启后生效，重启前先让运行中的任务结束。已持久化的模型锁和设置原样保留，不需要数据迁移。
