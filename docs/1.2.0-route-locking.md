# 1.2.0：用户选模锁定与 DSH 适配

适配基线：[DSH 0.2.1-rc.3](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.3)。验证日期：2026-10-26。

## 行为变更

子代理路由按以下顺序决定：**父会话的子代理选择 > 设置中的子代理默认 > 宿主确认的父会话当前或待生效主模型**。

工具参数、原生启动参数和预设中的 provider、model、reasoning effort 不能覆盖用户选择。冲突偏好记录在子代理锁中；非路由参数仍由原生流程处理。模型与思考强度整体决定，未指定强度时使用目标模型自己的默认值。

每个子代理首次请求前写入不可变锁。聊天栏改选只影响之后新建的子代理，已有子代理及其嵌套委派继续使用自己的锁。续聊、重试与重启恢复不会根据新的全局默认重新推算。

进入计划模式仍临时使用制定计划模型；批准或退出后，首条执行请求恢复进入计划前的主模型和思考强度。会话换模不修改新会话默认设置。子代理内部不参与计划换模。

## 请求保护

- 包装实际存在的 `startActivation`、`startContinuable` 和 `start`，保留原生权限、取消、预设、目录、深度限制及生命周期。
- 创建公告完成前，原子写入锁并同步文件及目录；保存失败不承认锁定，也不放行请求。
- 子代理请求组装使用固定路由。最终 `llm/stream` 守卫只放行或拒绝，不改写已冻结的请求。
- 初始化失败时保留守卫。配置错误、模型不可用、锁损坏或身份不符时停止派发，没有自动换模兜底。
- 无法保证实际路由的外部后端拒绝启动。可信本机适配器内部的服务端模型映射和账单仍由提供方负责。
- 热重载时为已存在的本机子代理安装下一次请求的守卫，不取消已经在传输中的请求。

锁文件为 `$DSH_HOME/storages/model-switch/child-route-locks.json`，包含子代理与父会话身份、模型、来源、策略版本、修订标识及冲突记录。现有会话选择和设置的数据格式保持兼容。

## 历史子代理确认

历史子代理没有可靠锁记录时，下一次请求暂停；历史日志里出现过某个模型，不代表用户授权继续使用它。

1. 打开子代理，在标题栏展开“待确认模型”。
2. 选择模型和思考强度，点击“应用”。
3. 宿主确认保存后显示“已锁定”，通过原生续聊操作继续使用原上下文。

确认接口复用宿主认证，并核对父子关系。新版只接受 owner 身份；0.2.0 只接受原生 operator 实例。没有向模型注册任何确认工具。已经锁定的子代理不能通过该接口改模，需要不同模型时新建子代理。

标题栏显示用户指定、最近放行请求和选择来源。最近放行请求来自最终守卫的请求事实，不是模型自述，也不代表提供方已成功返回或账单确认。连接失败时撤销锁定状态显示；旧宿主未加载保护接口时提示重启，不将其描述为已经阻止请求。

## 验证

| 宿主版本 | 原生链路 | 结果 |
| --- | --- | --- |
| 0.2.1-rc.3 | `startActivation`、原生工具、嵌套、冷恢复、计划批准 | 通过 |
| 0.2.1-rc.2 | `startActivation`、原生工具、嵌套、冷恢复、计划批准 | 通过 |
| 0.2.1-rc.1 | `startActivation`、原生工具、嵌套、冷恢复、计划批准 | 通过 |
| 0.2.0-rc.2 | 旧启动入口、原生工具、嵌套、计划批准 | 通过 |

模拟模型运行完整原生宿主：父模型为模拟 Sonnet，工具请求模拟 Opus，用户锁定模拟 GLM。核对锁文件、`request/header` 和适配器派发，**Opus 派发次数为 0**。另行向原生 `llm.stream` 提交冻结的错误模型请求，确认它在适配器调用前被拒绝。

rc.3 还经过独立进程重启、修改全局默认后的续聊，以及历史确认测试：确认前子代理派发为 0；未认证或父子关系不符的确认均拒绝；用户确认另一模型后恢复请求，并保留原上下文。

少量真实流式验证共 6 次请求，仅使用 GLM 与 STEP：普通 GLM 对话、GLM 子代理、STEP 子代理、清除覆盖后跟随 GLM、中途开启 STEP 计划模式、批准后恢复 GLM。三组子代理均携带冲突的启动模型参数，锁记录、请求头与实际适配器派发一致；未向 Opus 发送真实请求。

单元与原生工具回归覆盖路由冲突、并发会话、保存竞态、损坏及写入失败、权限、嵌套继承、热重载、续聊、计划进入/批准/退出和默认设置隔离。

## 开发验证命令

```bash
npm ci
npm run typecheck
npm test
npm run build
```

完整宿主探针需要官方 DSH 的完整 `node_modules` 目录；脚本不下载宿主、不使用真实模型凭据，创建独立测试 profile：

```bash
DSH_TEST_MODULE_ROOT=/absolute/path/to/dsh/node_modules \
DSH_TEST_HOME=/absolute/path/to/new-test-home \
DSH_TEST_REPORT=/absolute/path/to/initial.json \
npm run test:host
```

保留该测试目录后，可在新进程中设置 `DSH_TEST_PHASE=resume`、`DSH_TEST_PREVIOUS_REPORT=/absolute/path/to/initial.json`，并指定新的报告路径，验证重启续聊。设置 `DSH_TEST_PHASE=historical` 会仅在带有测试标记的目录中移除目标子代理锁，验证暂停、认证、确认和上下文保留。

## 升级与问题来源

候选包、package 和运行时报告的插件版本均为 1.2.0，路由策略版本为 1。等待现有任务结束后，完全退出并重新打开 DSH；仅刷新页面不能激活宿主守卫。旧子代理需要上述确认流程，不会自动继承历史实际模型。

[PR #1](https://github.com/Dalizi2026/dsh-model-dispatch/pull/1) 指出了新版 `startActivation` 入口变化。本轮保留其问题来源与入口回归测试，沿用已存在的兼容实现，不重复套用旧补丁；未对该 PR 评论、合并或关闭。
